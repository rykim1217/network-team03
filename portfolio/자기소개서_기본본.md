# 자기소개서 기본본 초안

팀 프로젝트에서 보안 이벤트를 탐지한 뒤 실제 대응까지 연결하는 과정을 맡아 검증했습니다. 처음에는 대량 로그가 Graylog로 직접 몰릴 때 하위 시스템 장애가 발생하면 유실 여부를 확인하기 어렵고, n8n 알림 설정에도 팀 공용 Discord 봇 방식과 개인 채널 웹훅 방식이 섞여 있었습니다. 원인을 로그 수집 경로와 자동화 설정의 분리 부족으로 보고, SQLite WAL 기반 버퍼와 속도 제한·재시도 결과를 확인하는 테스트를 수행하는 한편 n8n의 Discord 알림을 Incoming Webhook 방식으로 통일했습니다. 저장소에는 실제 웹훅·토큰을 남기지 않고 placeholder와 `.env.example`만 제공하도록 정리했습니다.

그 결과 2만 건 스파이크에서 최종 queue lag 0, dropped 0, DLQ 0을 확인했고, 브루트포스 공격자의 IP 차단과 킬체인 CRITICAL/WARNING 분기를 실제 환경에서 재현했습니다. 또한 직접 실행이 성공한 시나리오와 Graylog production webhook에서 추가 확인이 필요한 시나리오를 구분해 기록했습니다. 이 경험을 통해 보안 자동화는 탐지 규칙을 만드는 것에서 끝나지 않고, 수집·분석·대응·복구와 비밀정보 관리까지 하나의 운영 흐름으로 검증해야 한다는 점을 배웠습니다.
